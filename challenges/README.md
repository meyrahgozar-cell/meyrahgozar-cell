# چالش گروهی کاهش وزن

سایت کامل، فارسی و راست‌به‌چپ برای چالش کاهش وزن با جدول وزن شروع / وزن فعلی / وزن تعهد پایان ماه، ثبت روزانه‌ی وزن (با ساعت اندازه‌گیری و وضعیت معده)، تحلیل هوشمند BMI و کالری، گزارش شخصی و جمعی، و قرعه‌کشی جایزه بر پایه‌ی کیلوهای تعهد.

- **بدون build و بدون ابزار:** فقط HTML، CSS و JavaScript خالص (ES Modules). کافی است فایل‌ها را روی هر هاست استاتیک (GitHub Pages، Netlify، هر سرور ساده) بگذارید.
- **تقویم شمسی:** تبدیل دقیق شمسی/میلادی، انتخابگر تاریخ شمسی، شمارش معکوس تا پایان دوره.
- **روی اسکیمای موجود:** نام، قد، سن و جنسیت از `profiles`، وزن‌ها از `user_weights`، وضعیت معده از `daily_logs` و سهم اشتراک از `app_settings` خوانده می‌شود؛ فقط دفتر چالش در جدول‌های `challenge_*` ذخیره می‌شود.

## ۱) انتشار روی GitHub Pages

1. همه‌ی فایل‌ها و پوشه‌ها (`index.html`، `assets/`، `supabase/`، `.nojekyll`) را در ریشه‌ی یک مخزن GitHub آپلود کنید.
2. **Settings → Pages → Source: Deploy from a branch → Branch: main / (root) → Save**
3. چند دقیقه بعد آدرس `https://USERNAME.github.io/REPO/` باز می‌شود.

> تا وقتی جدول‌های Supabase ساخته نشده باشند، صفحه‌ی「پایگاه‌داده در دسترس نیست」با راهنمای راه‌اندازی نمایش داده می‌شود؛ هیچ داده یا کاربر نمونه‌ای وجود ندارد. برای شروع، مرحله‌ی بعد را انجام دهید.

## ۲) فعال‌سازی پایگاه‌داده‌ی واقعی (Supabase)

پروژه‌ی شما: `https://zlvsmjhwyzfdecfyhxal.supabase.co`

1. در داشبورد Supabase وارد **SQL Editor** شوید.
2. محتوای فایل [`supabase/schema.sql`](supabase/schema.sql) را کامل اجرا کنید. این فایل **فقط افزودنی** است: جدول‌های چالش (`challenge_pledges`، `challenge_payments`، `challenge_settlements`) و سیاست‌های خواندن برای `profiles`/`user_weights` را می‌سازد و هیچ جدول یا داده‌ی موجودی را تغییر نمی‌دهد.
3. اگر می‌خواهید ثبت‌نام بدون تأیید ایمیل باشد: **Authentication → Providers → Email → Confirm email = off**
4. مدیر دوره کسی است که در `profiles` ستون `is_admin` او `true` باشد:

```sql
update public.profiles
   set is_admin = true
 where id = (select id from auth.users order by created_at asc limit 1);
```

سهم اشتراک هر دوره هم از `app_settings` خوانده می‌شود:

```sql
update public.app_settings set value = 300000 where key = 'challenge_fee';
```

5. صفحه را دوباره باز کنید؛ نشان «متصل به Supabase» باید در نوار بالا دیده شود و جدول چالش با داده‌ی واقعی بارگذاری شود.

کلید استفاده‌شده در `assets/js/config.js` همان کلید **publishable** است و برای مرورگر امن است. هرگز `service_role` را در فایل‌های سایت نگذارید.

### جدول‌هایی که چالش استفاده می‌کند

| جدول | وضعیت | کاربرد در چالش |
| --- | --- | --- |
| `profiles` | موجود | نام نمایشی، قد، سن، جنسیت، مدیر بودن و اجازه‌ی نمایش BMI |
| `user_weights` | موجود | هر وزن ثبت‌شده؛ وزن شروع = ثبت تعهد، وزن فعلی = آخرین ثبت دوره |
| `daily_logs` | موجود | وضعیت معده‌ی هر روز (`item_type = 'weight_stomach'`) |
| `app_settings` | موجود | سهم اشتراک دوره (کلید `challenge_fee`) |
| `challenge_pledges` | جدید | تعهد هر کاربر در هر دوره: وزن شروع، وزن تعهد، کیلوهای تعهد |
| `challenge_payments` | جدید | سهم اشتراک: مبلغ، وضعیت (در انتظار/تأییدشده)، روش و شماره پیگیری |
| `challenge_settlements` | جدید | نتیجه‌ی تسویه: وزن نهایی، تعهد، تعداد بلیت، واجد شرایط، برنده |

> دوره‌ها جدول جداگانه ندارند: هر دوره همان ماه شمسی است و کلید آن‌ها مثل `1405-09` در سه جدول `challenge_*` ذخیره می‌شود.

## ۳) امکانات

### صفحه‌ی اصلی
- جدول زنده‌ی همه‌ی شرکت‌کننده‌ها: **وزن شروع، وزن فعلی، تغییر، وزن تعهد پایان ماه، باقی‌مانده، BMI، درصد پیشرفت، وضعیت، تعداد بلیت**.
- جست‌وجو و فیلتر (در مسیر / به تعهد رسیده / پرداخت‌شده)، سکوی سه نفر اول، استخر جایزه، شمارش معکوس، برنده‌ی دوره‌ی قبل.

### ثبت وزن روزانه
- وزن با گام ۰٫۱، **ساعت اندازه‌گیری** (۶ تا ۲۳) و **وضعیت معده** (ناشتا / سبک / پر).
- انتخابگر تاریخ شمسی؛ ثبت هر روز یکتا است و ذخیره‌ی دوباره همان روز، آن را ویرایش می‌کند.
- لیست ثبت‌های اخیر با تغییر نسبت به ثبت قبل، حذف، و نمودار روند.

### پروفایل و الزامات BMI
- قد، سال تولد، جنسیت، سطح فعالیت، شهر.
- محاسبه‌ی BMI، دسته‌بندی، محدوده‌ی وزن سالم، BMI هدف و وزن متناظر، BMR و TDEE و سقف کالری.
- هدف زیر BMI ۱۸٫۵ پذیرفته نمی‌شود.

### مربی هوشمند
موتور تحلیل محلی (`assets/js/ai.js`) روی داده‌ی واقعی هر کاربر:
- رگرسیون خطی روند وزن، سرعت هفتگی، پیش‌بینی وزن پایان ماه، تشخیص فلات و روند صعودی.
- کیفیت اندازه‌گیری (ساعت ثابت، ناشتا بودن، نوسان)، درصد پایبندی، زنجیره‌ی ثبت.
- ریسک‌ها (کاهش خیلی سریع، BMI پایین، تعهد غیرواقعی، ثبت ناقص) و توصیه‌های کالری/پروتئین/آب/خواب/تمرین.
- گفت‌وگوی فارسی با تشخیص موضوع پرسش (فلات، کالری، شانس جایزه، BMI، اندازه‌گیری و…).

> این مربی یک موتور قاعده‌محور و محلی است و جایگزین پزشک یا متخصص تغذیه نیست. برای اتصال به یک مدل زبانی، فقط کافی است خروجی `analyze` را به API دلخواه بفرستید.

### گزارش شخصی
- نمودار وزن با خط تعهد، پیش‌بینی پایان ماه، خلاصه‌ی هفتگی، تحلیل کیفیت ثبت، همه‌ی ثبت‌ها و **خروجی CSV** و چاپ.

### گزارش کلی و جایزه
- جدول کامل رتبه‌بندی، بلیت‌ها و شانس هر نفر، شبیه‌سازی مونت‌کارلو (۵۰۰۰ قرعه‌کشی)، تاریخچه‌ی دوره‌های تسویه‌شده.
- پنل مدیر: تأیید پرداخت‌ها، پیش‌نمایش قرعه‌کشی، تسویه‌ی رسمی با بذر ثابت.

## ۴) فرمول جایزه

```
استخر جایزه      = مجموع سهم‌های پرداخت‌شده‌ی همان دوره
بلیت هر نفر      = حداکثر(۱، گرد شده‌ی کیلوگرم تعهد کاهش وزن)
شرط ورود        = وزن پایانی ≤ وزن تعهد  و  پرداخت تأییدشده
احتمال برد       = بلیت او ÷ مجموع بلیت‌های واجدین شرایط
```

قرعه‌کشی با یک مولد شبه‌تصادفی seeded (بذر = کلید دوره) انجام می‌شود؛ نتیجه در `challenge_settlements` ذخیره می‌شود و با همان بذر قابل بازتولید است.

### پرداخت
در این نسخه درگاه بانکی متصل نیست. کاربر پرداخت را با روش و شماره پیگیری ثبت می‌کند و مدیر دوره آن را تأیید می‌کند. برای اتصال درگاه (زرین‌پال و…) فقط باید تأیید سمت سرور اضافه شود؛ ساختار `challenge_payments` آماده است.

## ۵) ساختار پروژه

```
index.html                 پوسته‌ی اولیه
assets/css/                استایل‌ها (base, layout, components, pages)
assets/js/app.js           راه‌اندازی و مسیریابی هش‌محور
assets/js/config.js        آدرس/کلید Supabase، ثابت‌ها
assets/js/store.js         وضعیت مرکزی، احراز هویت، CRUD و محاسبات جدول
assets/js/db.js            کلاینت REST و Auth سوپابیس
assets/js/jalali.js        تقویم شمسی
assets/js/ai.js            موتور تحلیل و مربی
assets/js/lottery.js       قرعه‌کشی وزنی و شبیه‌سازی
assets/js/chart.js         نمودارهای SVG
assets/js/ui/              پوسته، مودال ثبت تعهد/پرداخت، انتخابگر تاریخ
assets/js/pages/           خانه، ثبت وزن، پروفایل، گزارش شخصی، گزارش کلی، مربی، قوانین، ورود
supabase/schema.sql        جدول‌های چالش + سیاست‌های دسترسی (افزودنی)
```

مسیرها: `#/` خانه، `#/log` ثبت وزن، `#/profile` پروفایل، `#/report` گزارش من، `#/coach` مربی، `#/overall` گزارش کلی، `#/rules` قوانین، `#/auth` ورود.

## ۶) نکات

- **دوره‌ها ماهانه و شمسی‌اند.** دوره‌ی جدید هنگام اولین ورود در ماه شمسی بعد به‌صورت خودکار ساخته می‌شود.
- **وزن فعلی** از آخرین ثبت روزانه‌ی هر کاربر خوانده می‌شود؛ اگر ثبتی نباشد، وزن شروع نمایش داده می‌شود.
- برای پایان دوره، ابتدا وزن‌های پایانی را ثبت کنید، بعد از پنل مدیر «تسویه و قرعه‌کشی رسمی» را بزنید.
- فونت وزیرمتن از CDN بارگذاری می‌شود؛ در صورت قطع بودن، فونت‌های سیستم جایگزین می‌شوند.
- کلید Supabase در `assets/js/config.js` قابل تغییر است.
